# Aura Engineering Principles

Every line of code should survive 5 years.

Never write code just because it works.

Write code because it scales.

---------------------------------------

Code should be

Readable

Reusable

Maintainable

Observable

Secure

Testable

---------------------------------------

Always prefer

Composition

Dependency Injection

Interfaces

Configuration

Small modules

---------------------------------------

Never

Duplicate Logic

Hardcode Secrets

Create God Classes

Write 1000-line files

Mix Business Logic with Controllers

---------------------------------------

Every service should have

API Layer

Application Layer

Domain Layer

Infrastructure Layer

Tests

Documentation

---------------------------------------

Every feature requires

Unit Tests

Integration Tests

Migration

Documentation

---------------------------------------

If two solutions exist,

always explain the tradeoffs.

Choose the production solution.

---------------------------------------

Aura should feel like software built by Stripe.

Not a hackathon project.
